Remaining deployment and content steps

  1. Serve the new build on https://www.matrixonline.in with status 200. Remove the current www-to-non-www redirect first, otherwise adding the opposite rule will create a loop.
  2. In only the beta HTTP/HTTPS virtual hosts, retain their TLS configuration and set return 301 https://www.matrixonline.in$request_uri;. Preserve each path and query. Redirect non-www and HTTP variants to the corresponding HTTPS www URL. No virtual hosts were changed by this task.
  3. At cutover, set the serving process APP_URL to https://www.matrixonline.in so the existing CSRF allowlist matches the public host. Preserve session code. Proxy headers: Host and X-Forwarded-Host = $host; X-Forwarded-Proto = trusted public scheme ($scheme when Nginx terminates TLS). Behind Cloudflare use Full (strict) and restrict direct application access.
  4. Restore the configured MongoDB service before production verification. The sitemap intentionally errors on DB outage rather than silently dropping job URLs. Re-run the crawler against the deployed build and its actual data.
  5. Review active job locations as City, Country (for example New Delhi, India), plus real title, summary and posting date. Ambiguous or incomplete records omit schema. No records were edited during this audit. Remote-only jobs need verified eligibility information before remote schema can be supported.
  6. Validate real active-job URLs with Google's Rich Results Test. Confirm closed/hidden records remain noindex/404 and absent from the sitemap. Submit the www sitemap and monitor Search Console after cutover.
